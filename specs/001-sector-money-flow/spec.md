# Feature Specification: A股板块资金流入流出可视化

**Feature Branch**: `001-sector-money-flow`

**Created**: 2026-07-02

**Status**: Draft

**Input**: User description: "A股板块资金流入流出可视化（含双口径、可插拔数据源、1分钟级盘中序列与7天回看、面向未来 agent 消费者的架构约束）"

## Clarifications

### Session 2026-07-02

- Q: 板块排行的展示范围（展示多少个板块）？ → A: 默认展示净流入 Top N + 净流出 Top N 的聚焦榜，并提供「查看全部」入口展示全量板块；数据层全量采集，仅展示层默认收敛。
- Q: 「资金强弱」默认按什么口径排序？ → A: 排序字段用户可选（主力净流入 / 总净额 / 各单档），默认按主力资金净流入排序。
- Q: 盘中定时采集由谁驱动？ → A: 应用内后台调度器（随服务启动，自动判断交易时段）；采集「一次动作」抽象为不依赖 Web 的独立入口，为未来切换到独立采集进程（B 方案）预留。
- Q: 板块内个股下钻的数据模型预留到什么程度？ → A: 结构预留——本期即建出个股表与板块-个股归属关系表（含归属生效日期），留空、不采数据、不暴露下钻接口。
- Q: 采集失败后是否补采？ → A: 盘中单次失败当场限次重试，仍失败则留断点、不回补盘中缺口；当日收盘后用日频接口补全当日最终值（日终确定值），并在数据上区分「盘中快照」与「日终补全值」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看板块资金流排行 (Priority: P1)

用户打开可视化页面，看到当前交易日 A 股各板块（行业板块或概念板块）按资金净流入金额排序的排行榜。用户能一眼看出哪些板块资金净流入最多（最受资金追捧）、哪些净流出最多（资金撤离），并能看到每个板块流入/流出了多少钱。

**Why this priority**: 这是整个功能的核心价值——不需要任何历史数据、不需要图表交互，只要能把「当日各板块资金强弱」这一张排行榜呈现出来，用户就已经获得了可用的判断依据。它是能独立交付的最小可用产品（MVP）。

**Independent Test**: 在一个有当日板块资金流数据的环境下打开页面，验证排行榜按净流入金额正确排序、金额显示准确、能区分净流入（正）与净流出（负），即可确认本故事独立可用。

**Acceptance Scenarios**:

1. **Given** 当日板块资金流数据已采集入库，**When** 用户打开可视化页面，**Then** 页面默认展示各板块按当日资金净流入金额排序的「净流入 Top N + 净流出 Top N」聚焦榜，每个板块显示其净流入/流出金额（含正负），并提供「查看全部」入口以展示全量板块。
2. **Given** 排行榜已展示，**When** 用户查看某个资金净流出的板块，**Then** 该板块以可区分的方式（如负值/不同配色）标示为净流出，并显示流出金额。
3. **Given** 排行榜已展示，**When** 用户查看采用东方财富口径的板块，**Then** 除净额外还可看到主力、超大单、大单、中单、小单五档资金各自的净流入金额。

---

### User Story 2 - 切换板块口径（东财 / 同花顺） (Priority: P2)

用户可以在两种板块口径之间切换：东方财富口径（提供主力/超大单/大单/中单/小单五档资金拆分）与同花顺口径（仅提供净额，无五档拆分）。切换后，排行与展示随所选口径更新，并明确告知用户当前口径能提供哪些指标。

**Why this priority**: 不同口径的板块划分与数据颗粒不同，用户需要按自己习惯（如更接近同花顺板块）来看。它增强了 P1 的价值，但即使只有单一口径，P1 也已可用，故列为 P2。

**Independent Test**: 在两种口径数据都可用时切换口径，验证排行数据随之改变、五档指标仅在东财口径下出现、切换过程有清晰的口径标识，即可确认本故事独立可用。

**Acceptance Scenarios**:

1. **Given** 页面默认展示某一口径的板块资金流，**When** 用户切换到另一口径，**Then** 排行与指标切换为该口径的数据，且界面明确标示当前口径。
2. **Given** 用户切换到同花顺口径，**When** 页面展示板块资金流，**Then** 只显示净额指标，且明确说明该口径不提供五档拆分（而非展示空白或误导性的零值）。
3. **Given** 用户切换到某一口径，**When** 该口径的当日数据尚未采集或采集失败，**Then** 页面清晰告知该口径数据暂不可用，而不是静默展示过时或空白数据。

---

### User Story 3 - 查看单板块资金流的时间动态与回看 (Priority: P3)

用户选中某个板块，查看它资金流随时间的变化：既能看当日盘中随时间推进的资金流动态曲线（1 分钟级颗粒），也能回看最近若干天内任一交易日的分钟级资金流序列，从而判断这个板块近几日是持续被资金追捧还是撤离、当日盘中是否在加速流入。

**Why this priority**: 排行（P1）回答「现在谁强」，时间动态与回看回答「趋势如何、是否在加速、这几天怎么走的」。它显著提升分析价值，但依赖更完整的分钟级采集与存储，且建立在 P1/P2 之上，故列为 P3。

**Independent Test**: 选中一个已积累多日 1 分钟级序列的板块，验证能展示当日盘中分钟序列、能回看最近 7 天内任一交易日的分钟序列、相邻数据点间隔符合时效目标，即可确认本故事独立可用。

**Acceptance Scenarios**:

1. **Given** 当日盘中已按目标间隔持续采集该板块的累计资金流快照，**When** 用户查看当日盘中动态，**Then** 页面展示当日随时间推进的分钟级资金流序列。
2. **Given** 系统已保留最近 7 天的分钟级序列，**When** 用户选择回看最近 7 天内的某一交易日，**Then** 页面展示该交易日该板块的分钟级资金流序列。
3. **Given** 盘中某次采集因数据源限流等原因失败，**When** 用户查看该时段的资金流序列，**Then** 序列中该时间点缺失被如实呈现（如断点），而非用推测值填充或让相邻点误导性地首尾相连。
4. **Given** 用户尝试回看超过保留窗口（当前为 7 天）之前的日期，**When** 该日期数据已不在保留窗口内，**Then** 页面明确告知该日期超出当前可回看范围，而非展示空白或错误数据。

---

### Edge Cases

- **新板块当日无数据**：当日出现的新板块在数据源返回为空时，系统不得因此报错中断整批采集，需容错并记录，其余板块数据正常入库与展示。
- **数据源限流 / 请求失败**：数据源（东财/同花顺）对高频请求限流或临时不可用时，单次采集失败不得污染已有数据，需当场有限次重试与降频；重试仍失败则留断点、不回补盘中缺口，并将失败如实记录，页面对应时点数据缺失需被诚实呈现。当日收盘后仍会用日频接口补全该日日终确定值。
- **达不到 1 分钟目标间隔**：当数据源限流导致无法维持 1 分钟采集节奏时，系统需自动放宽采集间隔（退化为 2、3…分钟），但任何情况下相邻快照间隔不得超过 10 分钟上限；实际达成的颗粒需可被用户/审计感知。
- **口径不提供某指标**：同花顺口径无五档拆分时，界面必须显式说明「该口径不提供」，不得以 0 值冒充真实数据。
- **非交易时段 / 休市**：非交易时段访问时，展示的是最近一个交易日的收盘态数据，并明确标注数据所属交易日与采集时间，避免用户误以为是实时值。
- **回看窗口边界**：用户请求超出当前保留窗口（7 天）的历史时，系统需明确告知超出范围，而非返回空白或误导数据。
- **金额精度**：大额资金（亿级）在聚合、排序、展示过程中不得因数值类型丢失精度或产生舍入误差导致排序错乱。
- **两口径板块不可直接混比**：东财与同花顺的板块划分口径不同，系统不得把两种口径的板块金额直接放在同一排行里相互比较。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 采集并持久化 A 股行业板块与概念板块的当日资金净流入金额，以金额（货币）为核心指标。
- **FR-002**: 系统 MUST 支持东方财富与同花顺两种板块口径，用户 MUST 能够在两者之间切换查看；界面 MUST 明确标示当前所用口径。
- **FR-003**: 对东方财富口径，系统 MUST 提供主力、超大单、大单、中单、小单五档资金各自的净流入金额；对同花顺口径，系统 MUST 提供净额，并 MUST 明确告知该口径不提供五档拆分。
- **FR-004**: 系统 MUST 提供当日各板块按资金净流入金额排序的排行，并 MUST 能区分净流入（正）与净流出（负）。排序字段 MUST 可由用户选择（主力净流入 / 总净额 / 各单档），默认按主力资金净流入排序。展示 MUST 默认呈现「净流入 Top N + 净流出 Top N」聚焦榜并提供「查看全部」入口；数据采集 MUST 覆盖全量板块，展示范围收敛仅发生在展示层。
- **FR-005**: 系统 MUST 在交易时段内以定时快照方式采集当日累计资金流，形成盘中时间序列；采集间隔的目标为 1–3 分钟，MUST NOT 超过 10 分钟上限。盘中采集 MUST 由应用内后台调度器驱动（随服务启动、自动判断交易时段）；「采集一次」的动作 MUST 抽象为不依赖 Web 层的独立入口，以便未来在不改动采集业务逻辑的前提下切换为独立采集进程或外部调度触发。
- **FR-006**: 系统 MUST 将盘中采集组织为 1 分钟级颗粒的板块资金流序列（由定时快照近似得到），以支持分钟级的动态展示与回看。
- **FR-007**: 系统 MUST 至少保留最近 7 天的分钟级板块资金流序列供用户回看；数据模型与存储 MUST 为将保留窗口扩展至 30 天预留能力，但本期只需实现 7 天。
- **FR-008**: 用户 MUST 能够回看保留窗口内任一交易日某板块的分钟级资金流序列；当请求超出保留窗口时，系统 MUST 明确告知超出可回看范围。
- **FR-009**: 系统 MUST 提供以编程方式查询板块资金流（排行、单板块序列、指定日期回看）的能力，查询结果 MUST 结构稳定、字段自描述，且错误情形 MUST 以结构化、可被程序理解的方式返回（而非裸异常/未定义行为）。
- **FR-010**: 系统 MUST 提供一个可直接打开的可视化界面，展示板块资金强弱排行、当日盘中动态与历史回看，帮助用户理解数据。
- **FR-011**: 系统 MUST 将「获取原始数据的来源」与「对上层提供的板块资金流能力」解耦，使得未来更换或新增数据来源时，上层查询能力与对外接口 MUST NOT 因此改变。
- **FR-012**: 面向人的可视化界面与面向未来自动化消费者（agent）的查询能力 MUST 建立在同一份业务能力之上，MUST NOT 各自实现一套独立的取数/计算逻辑。
- **FR-013**: 本期对外能力 MUST 全部为只读查询；系统 MUST 在能力划分上将「只读查询」与「未来可能引入的动作型能力」清晰分离，为后续引入人工确认（human-in-the-loop）预留位置。
- **FR-014**: 系统 MUST 对数据源限流、当日新板块返回空、单次采集失败等已知异常具备容错能力，单点失败 MUST NOT 破坏已有数据或中断整批采集；在限流时 MUST 能自动放宽采集间隔并保持在 10 分钟上限内。盘中单次采集失败 MUST 当场进行有限次重试；重试仍失败时 MUST 留断点、MUST NOT 回补盘中缺口，也 MUST NOT 以推测值填充。
- **FR-015**: 系统 MUST 对每次采集运行及其异常进行结构化记录（含时间、口径、板块范围、实际达成的采集间隔、结果/失败原因），以支持事后审计与问题追溯。
- **FR-016**: 金额相关数值在采集、聚合、排序、展示的全过程中 MUST 保持精度，MUST NOT 因数值处理丢失精度或导致排序错误。
- **FR-017**: 当某口径或某时点的数据不可用（未采集/采集失败/休市/超出回看窗口）时，系统 MUST 如实告知数据缺失或标注数据所属交易日与采集时间，MUST NOT 以推测值或过时值冒充当前有效数据。
- **FR-018**: 数据模型 MUST 为后续「板块 → 个股下钻」（查看某板块内资金具体流向哪些个股）预留扩展位置：本期即建立个股实体与「板块-个股归属关系」实体（含归属生效日期以支持历史成分回看），但本期 MUST 保持其为空、MUST NOT 采集个股数据、MUST NOT 暴露个股下钻接口。
- **FR-019**: 当日收盘后，系统 MUST 使用日频接口补全当日各板块的最终确定值（日终值），以保证每个交易日至少有一个可靠的日终完整记录；系统 MUST 在数据上区分「盘中快照」与「日终补全值」两种来源，MUST NOT 将两者混淆或让日终值污染盘中分钟序列的真实断点。

### Key Entities *(include if feature involves data)*

- **板块 (Sector)**：一个可被观察资金流的 A 股板块。关键属性：所属口径（东财/同花顺）、板块类型（行业/概念）、板块名称/标识。同一现实板块在不同口径下可能有不同划分，不可跨口径直接等同。
- **板块资金流记录 (Sector Money Flow Record)**：某板块在某一时间点（当日某盘中分钟时刻、或某历史交易日的分钟时刻）的资金流量化观测。关键属性：所属板块、口径、观测时间（交易日 + 分钟级时间戳）、**数据来源类型（盘中快照 / 日终补全值）**、净流入金额，以及（仅东财口径）主力/超大单/大单/中单/小单五档净流入金额。该实体承载 1 分钟级序列与 7 天回看。
- **个股 (Instrument)**：一只 A 股标的。关键属性：证券代码、名称、所属市场。**本期建立但保持为空、不采集数据**，为未来「板块 → 个股下钻」预留。
- **板块-个股归属关系 (Sector Constituent)**：某个股在某段时间内归属于某板块的成分关系。关键属性：所属板块、所属个股、口径、**归属生效日期区间**（板块成分会调整，记录生效区间以支持历史成分的可复现回看）。**本期建立但保持为空、不采集数据**。
- **采集运行记录 (Ingestion Run)**：一次数据采集动作的审计记录。关键属性：运行时间、目标口径与板块范围、实际达成的采集间隔、成功/失败结果、失败原因、覆盖的时间点，用于可观测性与事后追溯。
- **数据来源 (Data Source)**：为上层提供板块资金流原始数据的来源抽象。关键属性：来源标识、所支持的口径与指标能力。上层业务不感知具体来源实现。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户打开可视化页面后，能在 5 秒内看到当日板块资金净流入排行，并据此判断出资金净流入最多与净流出最多的板块。
- **SC-002**: 在东方财富口径下，用户查看任一板块时都能获得净额与五档（主力/超大单/大单/中单/小单）共 6 项金额指标。
- **SC-003**: 交易时段内，板块盘中资金流序列相邻数据点的时间间隔目标为 1–3 分钟，且在任何情况下均不超过 10 分钟。
- **SC-004**: 用户可回看最近 7 天内任一交易日某板块的分钟级资金流序列，数据点保持分钟级颗粒（不因回看而降采）。
- **SC-005**: 当某数据源单次采集失败时，已入库的其他板块与其他时点数据 100% 不受影响，且失败被完整记录、可被查询到。
- **SC-006**: 亿级金额在排序与展示中 0 精度损失——同一批数据的排序结果可稳定复现，不因数值处理产生舍入导致的排序偏差。
- **SC-007**: 新增一种数据来源实现时，无需修改可视化界面与对外查询接口即可接入（面向未来的可插拔性验证）。
- **SC-008**: 面向 agent 的查询能力可用一致的结构化结果与结构化错误被程序消费，无需人工解析非结构化文本即可判断成功/失败与数据内容。
- **SC-009**: 保留窗口内每个交易日 100% 具备一条可靠的日终确定值记录（即使当日盘中存在采集断点），且日终值与盘中快照在数据上可明确区分。

## Assumptions

- **本期仅覆盖 A 股板块资金流**：北向资金归因到板块因监管自 2024 年改为季度披露、免费数据源无法支撑实时/日频，明确不纳入本期；南向资金同样不在本期范围。
- **时效性为「尽力而为」**：盘中信息延迟可接受 10 分钟以内，目标 1–3 分钟；实际颗粒取决于数据源能力与限流，不承诺逐秒实时。
- **1 分钟序列由定时快照近似得到**：数据源仅提供当日累计资金流快照，1 分钟级盘中序列由系统按 1–3 分钟间隔轮询快照后自行组织，并非数据源直接提供的原生分钟序列；限流时会自动放宽间隔（上限 10 分钟）。
- **回看窗口本期为 7 天**：先保留最近 7 天的分钟级序列，用于观察真实数据量后再决定是否扩展至 30 天；存储结构为 30 天预留但本期不实现。
- **首个数据来源基于开源数据（akshare 封装的东财/同花顺免费接口）**：数据可用性、字段口径与稳定性受该免费来源约束；架构上保持来源可替换，未来可接入付费/券商数据源。
