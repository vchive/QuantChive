# Feature Specification: 资金档位博弈可视化 + 多源数据层增强

**Feature Branch**: `005-flow-tier-battle-viz`

**Created**: 2026-07-05

**Status**: Draft

**Input**: 见下方"用户输入"——经两轮 GitHub 调研（资金流可视化设计 + 开源先例/架构最优性）+ 一轮数据源实测调研（大厂/多源）+ 5 轮数据层决策讨论后的完整设计。

## 背景

QuantChive 是通用市场观测平台。资金流是首个指标，但当前展示很死板（单指标折线 + 表格），**四档资金博弈根本没画进去**。本 feature 把平台的核心差异化价值做出来：**看各资金档位（超大单/大单/中单/小单）的流入流出博弈，如何驱动价格**。

调研确认（21 智能体核实）：开源界 **0 命中**"A股预分类档位 + 主力vs散户对抗 + 资金-价格背离"的完整组合——概念/数据/技术各零件都被做透，但这个组合无人做。**护城河是叙事与可视化，不是算法。**

三种博弈是核心：①**主力(超大+大) vs 散户(中+小)** 的净额对抗；②**同档位内部买卖对抗**（超大单买 vs 超大单卖，需流入流出）；③**资金流与价格背离**（价跌但主力累计净流入=吸筹）。

## Clarifications

### Session 2026-07-05

- Q: gross 怎么存？ → A: observation 加 4 个档位成交额列（超大/大/中/小），不加主力gross；流入/流出=(gross±net)/2 查询时算不落库；个股存、板块由成分求和派生、ETF不适用；加"四档gross全有或全无"CHECK。
- Q: 存储分层与降采时机？ → A: 分钟保留7天 → 小时(7天~3月, 降采取小时末累计快照) → 日线(放宽>3月)；降采/清理盘后每天一次，不实时降采。
- Q: 百度源定位？ → A: 校验探针——收盘后随机抽样几十只+轮换覆盖，取当日四档跟新浪对比；不做数据主力（有反爬需无头浏览器，只有当日快照）。
- Q: 盘中层做什么？ → A: 做 A（净额逐分钟，东财 clist 全市场批量）；同档买卖（流入流出）盘中无源做不了（物理天花板）；待下周开盘探新浪实时接口。
- Q: 校验不一致怎么处理？ → A: 三级——①恒等式自检(硬错拒入库)②跨源方向+量级抓异常(口径差异不报)③只标记记审计+前端角标，绝不自动改数。
- Q: Tushare 备源？ → A: 只预留适配器接口，暂不实现，用户需要时开通token。
- Q: 教学？ → A: 不进产品（产品保持专业），术语讲解由单独文档交付。
- Q: 背离(价跌主力吸筹)自动识别用什么规则？ → A: **简单方向背离**——窗口内价格净跌 且 主力累计净额净升（方向相反）即标记吸筹；反之（价涨主力累计净降）标记派发。简单可测，MVP 首选，后续可升级量化背离度。
- Q: 累计主力净额曲线从哪起算？ → A: **全程绝对累计**——从该主体数据最早日累加（A/D线/CVD 标准做法），线形稳定不随缩放变；后端算一次下发。

## User Scenarios & Testing

### User Story 1 - 看个股各档位博弈 + 价格背离（历史四档）(Priority: P1) 🎯 MVP

作为观测者，我要在个股详情看到"四个资金档位（超大/大/中/小）逐日的流入流出博弈，以及它如何反映到价格"——尤其"价格在跌但主力（超大+大）持续净流入"这种吸筹背离信号。

**Why this priority**: 这是核心差异化价值、数据现成（新浪四档已灌）、补个 gross 列即可做，"先跑起来"最快见效的一版。开源 0 命中的组合就落在这。

**Independent Test**: 对一只已回填的股（如中国船舶），查其四档时序：main_net/各档 net 有值、各档流入流出=(gross±net)/2 算出且恒为整数、累计主力净额曲线由后端算好、价格对齐同一时间轴；断点 null 不连线。全程 mock 可测不联网。

**Acceptance Scenarios**:
1. **Given** 个股有新浪四档 gross+net 历史, **When** 请求多档对齐时序, **Then** 一次返回超大/大/中/小各档(净额+流入+流出) + 主力 + 价格 + 涨跌，对齐同一日期轴。
2. **Given** 某档 gross+net, **When** 后端算流入流出, **Then** 流入=(gross+net)/2、流出=(gross-net)/2 恒为整数分，且 流入-流出==净额、流入+流出==成交额。
3. **Given** 价格下跌区间但主力累计净额上行, **When** 展示, **Then** 该背离（吸筹）被自动识别/高亮（非教学提示，是分析信号）。
4. **Given** 某源只有净额无 gross（东财/baostock行）, **When** 查流入流出, **Then** 该档流入流出为空（诚实缺失，不伪造），净额仍可展示。

### User Story 2 - 专业可视化（ECharts 四档博弈图，替代死板折线）(Priority: P1)

作为观测者，我要专业、流动、高效的图（对标东财/同花顺），而非单折线+表格。含：价格 + 四档双向堆叠柱 + 累计主力/散户线的复合主图，能缩放联动、十字光标同步。

**Why this priority**: 可视化是本 feature 的护城河所在；没有它数据白灌。与 US1 数据同期。

**Independent Test**: 前端加载个股 → 渲染复合主图（价格pane + 四档柱pane + 累计线pane），红涨绿跌、四档同色系明度递进、主力/散户分色组；缩放三pane联动、光标同步；金额只显示不在前端算。

**Acceptance Scenarios**:
1. **Given** 多档对齐时序数据, **When** 渲染主图, **Then** 上格价格、中格四档净流入向上/流出向下双向堆叠柱、下格累计主力vs散户线，三格共享时间轴。
2. **Given** 用户缩放/悬停, **When** 交互, **Then** 三格 dataZoom 联动、十字光标跨格同步、图例可隐藏某档。
3. **Given** 涨跌与流入方向, **When** 着色, **Then** 守 A股语义（红=流入/涨、绿=流出/跌），不用绿入红出。

### User Story 3 - 盘中逐分钟净额回放 (Priority: P2)

作为观测者，交易日我要逐分钟看"主力 vs 散户净额"的拉锯回放，价格竖线随帧移动，看"某分钟主力放量→随即价格拐头"的因果。

**Why this priority**: 兑现"流动/动态"诉求，但盘中只有净额（无流入流出，物理天花板）、依赖调度器盘中运行、要开盘才有真数据——故 P2。

**Independent Test**: 注入 mock 分钟序列 → 时间轴回放，四档净额柱逐帧"长出"、价格竖线随帧移动；拖动定格任意分钟。全程 mock 不联网。

**Acceptance Scenarios**:
1. **Given** 盘中每分钟采的东财 clist 净额快照, **When** 归档, **Then** 落库为分钟序列（granularity='1min'），各档只有净额。
2. **Given** 当日分钟序列, **When** 回放, **Then** 四档净额柱逐分钟推进 + 价格竖线随帧移动 + 可拖动定格。
3. **Given** 非交易日或无当日分钟数据, **When** 请求盘中, **Then** 优雅提示"无分钟数据"，不伪造。

### User Story 4 - 多源主备校验（数据可信）(Priority: P2)

作为平台维护者，我要多个独立源交叉校验资金流数据，发现异常时标记（不改数），让数据可信。

**Why this priority**: 数据可信是分析价值的前提，但不阻塞首版可视化——故 P2。

**Independent Test**: mock 新浪+百度同股当日四档 → ①恒等式不成立的数据拒绝入库记审计；②方向相反/量级差>3倍标记分歧；③口径差异（数值不同但方向量级合理）不报；④分歧只标记不改数。

**Acceptance Scenarios**:
1. **Given** 一条 gross 数据 流入-流出≠净额, **When** 入库校验, **Then** 判定数据坏，拒绝入库，记审计。
2. **Given** 新浪与百度当日同股四档方向相反, **When** 跨源校验, **Then** 标记"口径分歧"，记审计，前端来源角标显示 ⚠️，数据不被改动。
3. **Given** 新浪与百度数值有差但方向一致、量级相近, **When** 校验, **Then** 判为正常口径差异，不报警（不能要求各源相等）。

### User Story 5 - 板块档位博弈（成分派生）(Priority: P3)

作为观测者，我要看板块级的各档位博弈（如"军工板块超大单在流入"）——由成分股档位求和派生。

**Why this priority**: 扩展到板块层，价值高但依赖个股 gross 就绪 + 求和聚合，故 P3。

**Independent Test**: mock 板块成分股各有四档 gross → 板块四档 = 成分求和（≥覆盖率门禁），派生正确、覆盖不足时不落假值。

**Acceptance Scenarios**:
1. **Given** 板块成分股都有四档 gross, **When** 派生板块四档, **Then** 板块各档 = 成分对应档求和，覆盖率≥门禁才落。
2. **Given** 成分覆盖率不足门禁, **When** 派生, **Then** 不落假板块值（宁缺勿假）。

### Edge Cases

- **只有净额无 gross 的源**（东财/baostock）：该行四档 gross 全 NULL，流入流出为空，净额仍展示——诚实缺失。
- **盘中无 gross**：盘中只能净额博弈，同档买卖对抗留空并说明"盘中无此数据"。
- **各源口径差异**：新浪超大单阈值 ≠ 东财/百度，数值本就不同——校验抓方向/量级异常，不要求相等。
- **降采累计值**：净额/gross 是当日累计，降采取小时末快照（非求和/平均），否则数值错。
- **超保留窗**：分钟/小时超 3 月清理后请求 → OutOfWindow，不插值。
- **THS 源只净额**：能力门禁自动降级为单条 main_net 线，不画四档。
- **ETF 无档位**：ETF 请求四档 → 能力门禁拒绝或降级，不伪造。
- **Tushare 未开通**：适配器预留但 is_active=0，路由跳过，不阻塞。
- **百度反爬/无头浏览器不可用**：校验探针降级跳过，不阻塞主链路。

## Requirements

### Functional Requirements — 数据层

- **FR-001**: observation 表 MUST 加 4 个档位成交额列（super_large/large/medium/small_gross_cents），整数分；不加主力 gross（可由超大+大推）。
- **FR-002**: 系统 MUST 在查询时算流入=(gross+net)/2、流出=(gross-net)/2（恒为整数分），不落库流入流出。
- **FR-003**: gross MUST 加"四档全有或全无"CHECK（新浪行全有、无gross源行全NULL）。
- **FR-004**: 存储 MUST 三层分级：分钟(1min,留7天) → 小时(hourly,7天~3月,降采取小时末累计快照) → 日线(daily,放宽>3月)；降采/清理盘后每天一次。
- **FR-005**: 板块四档 MUST 由成分股档位求和派生（≥覆盖率门禁，仿大盘求和），不单独抓源；ETF 四档不适用。

### Functional Requirements — 多源

- **FR-006**: 系统 MUST 以能力（有无gross/历史深度/独立后端）路由源；新浪(主,四档gross历史)、百度(校验探针,当日四档)、东财(净额/盘中)；复用现有选源工厂+metric_source。
- **FR-007**: 系统 MUST 预留 Tushare 适配器接口但暂不实现（is_active=0，路由跳过）。
- **FR-008**: 百度源 MUST 经无头浏览器取数（page.evaluate 内 fetch 绕 Acs-Token 反爬），定位为校验探针（收盘后抽样+轮换），不做数据主力；不可用时降级不阻塞。

### Functional Requirements — 校验

- **FR-009**: 系统 MUST 入库前恒等式自检（流入-流出==净额、流入+流出==成交额），不成立则拒绝入库并记审计。
- **FR-010**: 系统 MUST 跨源抓异常（方向相反 或 量级差>阈值默认3倍 → 标记分歧），但数值有差而方向量级合理 MUST 判为正常口径差异不报。
- **FR-011**: 校验分歧 MUST 只标记 + 记审计 + 前端来源角标提示，绝不自动改数据、不弹窗。

### Functional Requirements — 后端

- **FR-012**: 系统 MUST 提供多档对齐时序端点：一次返回超大/大/中/小各档(净额+流入+流出) + 主力 + 价格 + 涨跌 的对齐序列（gap 用 null）。
- **FR-013**: 累计净额（CVD/A-D 式）MUST 后端用整数分求和后下发；**全程绝对累计**（从主体数据最早日累加，线形稳定不随缩放变，算一次）；金额算术全在后端，前端只画不算。
- **FR-014**: 系统 MUST 支持盘中每分钟归档东财 clist 净额快照为分钟序列（依赖调度器盘中运行）。

### Functional Requirements — 前端

- **FR-015**: 前端 MUST 用图表库替换死板折线，渲染复合主图（价格 + 四档双向堆叠柱 + 累计主力/散户线），三格共享时间轴、缩放联动、光标同步。
- **FR-016**: 着色 MUST 守 A股语义（红=流入/涨、绿=流出/跌），四档同色系明度递进、主力/散户分色组。
- **FR-017**: 前端 MUST 诚实分级：历史用日线、盘中用分钟；断点 null 不连线；超窗/无数据优雅提示不插值；复用能力门禁（THS降级单线、板块拒价格排序、ETF无档位）。
- **FR-018**: 盘中回放 MUST 支持时间轴逐帧播放 + 价格竖线随帧移动 + 拖动定格。
- **FR-019**: 背离 MUST 被自动识别并可视化高亮（分析信号，非教学）：**简单方向背离规则**——窗口内价格净跌 且 主力累计净额净升 → 标记"吸筹"；价格净升 且 主力累计净额净降 → 标记"派发"。规则可测（给定序列判定确定）。

### 贯穿约束（宪章）

- **FR-020**: 金额 MUST 整数分、禁 float；流入流出=(gross±net)/2 保证整数；多源归一保标度（宪章 III）。
- **FR-021**: 历史 MUST 真实交易日、盘中当日累计、降采取真实末值（宪章 II 无前视）。
- **FR-022**: 校验/盘中采集/恒等式自检 MUST 记审计三态；只标记不改数（宪章 V）。
- **FR-023**: 源适配/gross推导/降采/校验/端点 MUST mock 可测不联网；百度无头浏览器可注入 mock（宪章 IV）。

### Key Entities

- **档位成交额（gross）**：observation 新增的 4 档成交额列；与已有 4 档净额配对，是推流入流出的原子数据。
- **流入/流出（派生）**：(gross±net)/2，查询时算不落库。
- **源能力（Capability）**：源声明 有无gross/历史深度/独立后端/是否启用，编排层按能力路由。
- **校验记录（audit）**：跨源分歧/恒等式失败的审计，只读不改数。
- **时间分层**：同一观测按 granularity（1min/hourly/daily）分层存储与保留。

## Success Criteria

- **SC-001**: 个股能展示四档（超大/大/中/小）的净额 + 流入 + 流出 + 主力 + 价格的对齐时序，流入流出满足恒等式、恒为整数分。
- **SC-002**: 用户能一眼看出"价跌但主力累计净流入"的吸筹背离（按简单方向背离规则自动高亮），无需读数字。
- **SC-003**: 主图专业化——四档博弈 + 价格 + 累计线三格联动缩放/光标同步，替代原单折线+表格。
- **SC-004**: 多源校验：恒等式坏数据 100% 拒入库；跨源方向反/量级差>3倍 100% 标记；口径差异不误报；分歧只标记零改数。
- **SC-005**: 存储三层分级生效，全市场 3 个月总量在数 GB 内可控；降采取小时末累计快照数值正确。
- **SC-006**: 盘中（交易日）能逐分钟回放主力vs散户净额拉锯 + 价格竖线随帧移动。
- **SC-007**: 全部源适配/推导/降采/校验/端点/前端逻辑 mock 可测不联网，测试全绿。

## Assumptions

- **各档位 gross 源现实**：能推流入流出的 = 新浪(主,深历史) + 百度(当日,校验) + Tushare(预留);盘中(东财clist)只有净额——"盘中同档买卖"是物理天花板非缺陷。见记忆 flow-tier-data-sources。
- **不向前兼容**：全新项目，加 gross 列走重建（沿用 spec004 重建库流程），无迁移代码。
- **口径差异正常**：各源"超大单"阈值定义不同，校验抓异常不求相等。
- **盘中依赖调度器**：复用 spec003 调度器盘中运行；周末/非交易时段无实时数据。
- **教学出文档**：术语与看图指南单独 markdown 交付用户，不进产品 UI。
- **前端库**：单库承载四档柱/热力/镜像面积/象限散点/时间轴回放（调研推荐 ECharts，plan 阶段确认）。
- **待办**：下周开盘探新浪实时接口是否带 gross（可能推翻"盘中只净额"）——见记忆 todo-probe-sina-realtime-intraday。

## 范围外（本期不做）

- Tushare 实现（仅预留接口）。
- 盘中流入流出（无源）——盘中只净额。
- 富途源（需本地网关）。
- 教学 UI 层（术语气泡）——文档交付。
- 观测模型三表核心结构变更（只加 gross 列 + 端点 + 前端）。
- footprint/逐笔 tick 微观订单流（需 tick 数据，远期专家视图）。
